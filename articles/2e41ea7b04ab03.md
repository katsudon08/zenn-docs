## はじめに

Reactでコンポーネントを作るとき、`ref` の扱いや props の型定義に悩んだ経験はないでしょうか。この記事では `forwardRef` の役割から始めて、TypeScriptと組み合わせた型安全なコンポーネント設計、そして React 19 以降の新しい書き方まで順を追って整理します。

## forwardRef とは

`forwardRef` は、親コンポーネントから子コンポーネントの DOM ノードに `ref` を渡せるようにする API です。

通常、関数コンポーネントに `ref` を直接渡すことはできません。

```tsx
const MyInput = (props) => <input {...props} />;

function Parent() {
  const ref = useRef(null);
  return <MyInput ref={ref} />; // ref が届かない
}
```

`forwardRef` を使うと、この制約を回避できます。

```tsx
const MyInput = forwardRef<HTMLInputElement, React.InputHTMLAttributes<HTMLInputElement>>(
  (props, ref) => {
    return <input ref={ref} {...props} />;
  }
);

function Parent() {
  const inputRef = useRef<HTMLInputElement>(null);

  const focusInput = () => {
    inputRef.current?.focus();
  };

  return (
    <>
      <MyInput ref={inputRef} placeholder="入力してください" />
      <button onClick={focusInput}>フォーカス</button>
    </>
  );
}
```

第一型引数に `ref` が指す DOM 要素の型、第二型引数に props の型を渡します。

## InputHTMLAttributes を extends した props 設計

カスタムコンポーネントを作る際、よく使われる型定義パターンがあります。

```ts
export interface CheckboxProps extends InputHTMLAttributes<HTMLInputElement> {
  label?: string;
}
```

`InputHTMLAttributes<HTMLInputElement>` を `extends` することで、ネイティブの `<input>` が持つ `onChange`、`disabled`、`checked`、`name` などの属性をすべて引き継ぎつつ、独自の `label` prop を追加できます。使う側では以下のように書けます。

```tsx
<Checkbox
  label="利用規約に同意する"
  checked={isChecked}
  onChange={(e) => setIsChecked(e.target.checked)}
  disabled={isLoading}
/>
```

実装側では `...rest` でネイティブ属性をそのまま展開できるため、コードがすっきりします。

```tsx
const Checkbox = forwardRef<HTMLInputElement, CheckboxProps>(
  ({ label, ...rest }, ref) => {
    return (
      <label>
        <input type="checkbox" ref={ref} {...rest} />
        {label && <span>{label}</span>}
      </label>
    );
  }
);
```

他の要素でよく使う組み合わせも整理しておくと便利です。

| コンポーネント | extends する型 |
|---|---|
| `<Input>` | `InputHTMLAttributes<HTMLInputElement>` |
| `<Button>` | `ButtonHTMLAttributes<HTMLButtonElement>` |
| `<Select>` | `SelectHTMLAttributes<HTMLSelectElement>` |
| `<Textarea>` | `TextareaHTMLAttributes<HTMLTextAreaElement>` |
| 汎用ラッパー | `HTMLAttributes<HTMLDivElement>` |

## Omit で特定の属性を隠す

`InputHTMLAttributes` を素直に extends すると、内部で固定したい属性も外から渡せてしまいます。たとえば Checkbox コンポーネントに `type="text"` を渡せてしまうのは意図しない挙動です。

こういった場合に `Omit` が役立ちます。

```ts
export interface CheckboxProps extends Omit<InputHTMLAttributes<HTMLInputElement>, "type"> {
  label?: string;
}
```

`Omit<T, K>` は型 `T` からキー `K` を取り除いた新しい型を生成するユーティリティ型です。これにより `type` prop を渡そうとするとコンパイルエラーになります。

```tsx
<Checkbox type="text" />
// ❌ エラー: 'type' は CheckboxProps に存在しません
```

実装側では `type="checkbox"` を固定しているので、外から上書きされる危険がなくなります。

複数のキーを除外したいときは `|` で繋げます。

```ts
Omit<InputHTMLAttributes<HTMLInputElement>, "type" | "checked" | "defaultChecked">
```

## React 19 以降の書き方

React 19 からは `ref` が通常の prop として渡せるようになり、`forwardRef` は不要になりました。

```tsx
import { type InputHTMLAttributes, type Ref } from "react"

export interface CheckboxProps extends Omit<InputHTMLAttributes<HTMLInputElement>, "type"> {
  label?: string
  ref?: Ref<HTMLInputElement>
}

const Checkbox = ({ label, ref, ...rest }: CheckboxProps) => (
  <label>
    <input type="checkbox" ref={ref} {...rest} />
    {label && <span>{label}</span>}
  </label>
)

export default Checkbox
```

使う側の書き方は変わりません。

```tsx
const ref = useRef<HTMLInputElement>(null)

<Checkbox ref={ref} label="同意する" onChange={...} />
```

`forwardRef` との比較をまとめると以下の通りです。

| | `forwardRef`（React 18以前） | 通常の props（React 19以降） |
|---|---|---|
| ラッパー関数 | 必要 | 不要 |
| `ref` の位置 | 第2引数 | 通常の prop |
| 可読性 | ネストが深い | フラットで読みやすい |

`forwardRef` は React 19 で非推奨（deprecated）になったため、新規コードでは通常の prop として `ref` を受け取る書き方に統一するのがよいでしょう。

## おわりに

- `forwardRef` は親から子の DOM に `ref` を渡すための仕組みで、React 18 以前では必須だった
- `InputHTMLAttributes` を `extends` することで、ネイティブ属性を丸ごと引き継いだ props を定義できる
- 内部で固定したい属性は `Omit` で取り除くことでコンパイルレベルの誤用防止ができる
- React 19 以降は `ref` を通常の prop として扱えるため `forwardRef` は不要になった
